# Үйлчлүүлэгчийн авсан багц ба сайжруулах хүсэлт

## Ажилтанд

1. **Багц** хэсгээс үйлчлүүлэгчийн авсан багцыг сонгоно.
2. **Авсан багцыг тохируулах** дээр дарна.
3. Үйлчилгээ тус бүрийн **Үндсэн оролт**, **Урамшуулал**-ыг оруулна. Урамшууллыг оролтын тоо эсвэл үндсэн тооны хувиар өгч болно.
4. **Үндсэн 4 + урамшуулал 2 = нийт 6** эсвэл **үндсэн 4 + 50% = нийт 6** гэсэн тооцоо, ашигласан болон үлдсэн оролтоо шалгана.
5. Шаардлагатай бол нэр, дуусах огноо, нэмэх үйлчилгээгээ тохируулна. Өөрчлөх шалтгаанаа бичиж **Шалгаад хадгалах** дээр дарж батална.

Зөвхөн сонгосон хүний авсан багц өөрчлөгдөнө. Төлбөрийн дүн, борлуулалт, ашигласан оролтын түүх, ерөнхий багцын загвар болон бусад хүний багц өөрчлөгдөхгүй. Өмнөх үйлчилгээг хасахгүй; ашигласан оролтоос бага нийт эрх хадгалахгүй.

Хуучин багцын үндсэн/урамшууллын задаргаа бүртгэгдээгүй бол систем таамаглахгүй. Ажилтан баталгаатай тоог оруулна. Үйлчилгээ нь тодорхойгүй хуучин ашиглалт байвал эхлээд админтай тулгана. Хоёр хүн зэрэг зассан, эсвэл оролт шинээр бүртгэгдсэн бол хуучин дэлгэцийн засварыг хадгалахгүй: хааж дахин нээгээд шалгана.

## Туслах шийдэж чадаагүй үед

Одоогийн туслах нь дэмжигдсэн бичгэн командыг таньдаг; бүх өгүүлбэрийг ойлгодог ерөнхий AI биш. Танихгүй хүсэлт, үр дүнгүй болсон тодорхойгүй хайлт болон холбосон хадгалалтын алдааны үед админы **Сайжруулах хүсэлт** хэсэгт ерөнхий мэдэгдэл бүртгэнэ. Энэ нь системийн алдаа эсвэл шинэ боломж хэрэгтэйг дангаараа нотлохгүй.

Автомат мэдэгдэлд ажилтны сонгосон бүртгэл, асуудлын төрөл, үйлдлийн ангилал, хугацаа орно. Туслахад бичсэн эх өгүүлбэр, үйлчлүүлэгчийн нэр, утас, эрүүл мэндийн мэдээлэл, нууц түлхүүр, техникийн алдааны дэлгэрэнгүйг автоматаар илгээхгүй.

Ажилтан **Хүсэлт / явц → Сайжруулах хүсэлт** хэсэгт “Ямар боломж хэрэгтэй, одоо юу болж байна, ямар үр дүн хүсэж байна” гэдгийг хувийн мэдээлэлгүйгээр тайлбарлан баталгаажуулж илгээнэ. Админ **Шинэ → Шалгаж байна / Тодруулах зүйлтэй / Хийхээр төлөвлөсөн → Шийдсэн** төлөв болон хариу бичнэ. Ажилтан хариуг мөн хэсгээс харна. Бичиж буй админы хариуг автоматаар шинэчлэх үед арилгахгүй.

Энэ хувилбарын мэдэгдэл **систем дотор** байна. Админы хуудас нээлттэй, харагдаж байхад 30 секунд тутам шалгана. Браузер хаалттай үед и-мэйл эсвэл утасны push мэдэгдэл явуулахгүй. Холболт бүтэлгүйтвэл “илгээгдээгүй” гэж харуулна; илгээгдсэн мэт мэдэгдэхгүй.

Нэг ижил автомат ангиллыг сесс дотор дахин илгээхгүй; сервер дээр нэг өдрийн нээлттэй ижил төрлийн хүсэлтүүдийг нэгтгэнэ. Өөр асуудлын дэлгэрэнгүйг тусдаа гараар илгээж болно. Нэгдсэн ажилтны нэвтрэлт ашиглаж байгаа бол сонгосон ажилтны нэр нь тусдаа нууц үгтэй account-ийн баталгаа биш; одоогийн нэвтрэлтийн загварыг өөрчлөөгүй.

## Нийтлэхээс өмнөх шалгалт

- Migration: `20261123070204_customer_package_customization_staff_requests.sql`. Нэмэлт хүснэгт/RPC үүсгэнэ; хуучин багцыг бөөнөөр засахгүй.
- Бодит орчны backup/restore боломж, одоогийн main болон rollback deployment-ийг дахин шалгана. Бодит өгөгдөлтэй буцаах туршилт хийхгүй.
- Preview болон тусгаарласан backend дээр ажилтан/админы хоёр session: багц 4+2/4+50%, ашигласан хэмжээнээс бага, зэрэг засвар, ажилтан солих, дахин илгээх, хувийн хүсэлтийн харагдах эрх, админы хариу, холбоо тасрах, mobile дэлгэц.
- Anonymous/customer direct RPC хориг, өөр ажилтны нэрээр хадгалах хориг, давтан request ID болон stale snapshot хоригийг шалгана.
- Зөвшөөрсөн production release дээр migration-ийг нэг удаа хэрэгжүүлж, provider build болон custom domain-ийг шалгана. Жинхэнэ хэрэглэгчийн багцыг туршилтаар өөрчлөхгүй; зөвшөөрсөн туршилтын бүртгэл шаардлагатай.
- Буцаах үед өмнөх frontend deployment руу шилжиж болно. Шинэ хүсэлт болон custom edit түүхийг устгахгүй; шинэ хүснэгт/RPC-ийг үлдээнэ. Эрхийн тоог буцаах шаардлагатай бол ашиглалтыг дахин шалгасан, шалтгаантай шинэ засвар хийнэ.

## Автомат шалгалтын хүрээ

- `test-package-customization.mjs`: үндсэн/урамшууллын тооцоо, бутархай/хязгаар, аюулгүй үйлдлийн ангилал.
- `test-custom-package-inbox-db.mjs`: тусгаарласан PostgreSQL fixture; migration, RPC, эрх, төлбөр/ашиглалт/загвар хадгалагдах, хуучирсан засвар, хүсэлт/хариу.
- `test-custom-package-inbox-ui.mjs`: mobile editor, баталгаажуулалт, ажилтан солих, хүсэлт, давхардал, админы хариу, бичиж буй хариуг хадгалах, бүтэлгүй илгээлт.
- `test-staff-assistant-ui.mjs`: одоогийн туслахын ажлууд болон хувийн мэдээлэлгүй автомат хүсэлтийн холболт.
- `test-package-checkout-ui.mjs`, `test-staff-assistant.mjs`: өмнөх үйлдлийн regression шалгалт.

Эдгээр нь зохиомол өгөгдөлтэй шалгалт. Hosted Supabase/Vercel-ийн production end-to-end баталгаа биш. Жинхэнэ олон connection-ийн зэрэг transaction ачааллын тестийг орлохгүй.
